## 1 서론

### 게임 개요

마중불은 오봉에 본가로 돌아온 망자가 작은 물건을 움직여 가족에게 마지막 인사를 전하는 2D 공포 게임이다. 가족의 반응을 살피던 중, 움직인 물건 대신 보이지 않는 자신을 따라보는 존재를 발견한다. 플레이어는 그 존재의 유인을 거절하고 실제 가족에게 신호를 보내, 송별불을 통해 돌아가야 한다.

| 항목 | 내용 |
|---|---|
| 장르와 시점 | 민속 소재의 공포 어드벤처 / 규칙을 관찰하는 짧은 탐색 / 2D 측면 고정 시점 |
| 대상 | 짧은 이야기와 주변 반응을 읽는 탐색을 선호하는 PC 플레이어. 복잡한 전투 조작 없이 진행한다. |
| 플랫폼과 조작 | Windows PC / 키보드 이동과 상호작용 / 메뉴는 마우스 클릭 |
| 플레이 시간 | 초회 3~5분 목표. 실제 제한 시간은 두지 않으며, 재플레이는 더 짧아질 수 있다. 시간은 테스트에서 확인한다. |
| 목표와 결과 | 가족에게 인사를 남기고, 가족이 지키는 송별불을 통해 귀환하면 성공한다. 가짜 가족의 손을 잡으면 집에 남겨진다. |
| 제작 범위 | 1인 제작 / 4주 / 집 맵 1개 / 주요 NPC 2명 / 조작 물건 3개 / 성공 1개와 짧은 실패 1개 |

### 배경과 인물

주인공은 세상을 떠난 뒤 오봉에 집으로 돌아온 부모다. 집에는 성인이 된 자녀가 있다. 첫날에는 익숙한 가족의 모습을 지켜보며 작은 소리로 존재를 알린다. 사흘째 저녁에는 낯익은 모습의 다른 인물이 방에 나타난다. 이 인물은 귀환을 막고 망자를 집에 붙잡아 두려는 존재다. 정체를 설명하는 긴 대사 대신 시선과 행동으로 차이를 보여 준다.

### 풍습을 가져오는 범위

오봉의 맞이와 배웅, 마중불과 송별불, 오이 말과 가지 소의 이미지를 배경으로 삼는다. 린노지와 교토 공식 자료에는 조상이 빨리 돌아오고 천천히 떠나기를 바라는 마음과 불을 길잡이로 삼는 설명이 있다[3][4]. 본 작품의 귀성 안내서, 보이지 않는 망자의 능력, 가짜 가족과 귀환 조건은 이를 바탕으로 만든 허구의 규칙이다.

실제로 플레이하는 구간은 첫날의 짧은 귀가와 사흘째의 송별이다. 중간 하루는 전환 자막으로 생략한다. 마을 길과 저승은 별도 맵으로 만들지 않고, 집 안에서 일어난 일만으로 한 판을 마무리한다.

## 2 본론

### 기획 의도와 핵심 재미

가족에게 돌아온 망자는 자신이 다녀갔다는 사실을 알리고 싶다. 그러나 자신을 똑바로 보는 존재가 나타나는 순간, 알아봐 주기를 바라던 마음이 불안으로 바뀐다. 이 전환을 플레이어가 직접 움직여 확인하게 하는 것이 핵심이다.

**그림 1** 같은 행동에 대한 반응 차이. 왼쪽(첫날): 탁자 위 움직인 컵 — 실제 가족 — 플레이어 순으로 서 있고, 가족의 시선은 컵을 향한다. 오른쪽(사흘째): 같은 배치에서 가짜의 시선은 플레이어를 향한다. 두 그림 모두 "컵을 건드린 뒤 반대편으로 이동"하는 플레이어 동선이 표시된다. 시선 화살표와 인물 이름은 설계 주석이며 실제 게임에는 표시하지 않는다.

처음 컵을 움직였을 때 가족은 컵을 본다. 사흘째 같은 컵을 움직이면 낯익은 인물은 플레이어를 따라본다. 플레이어가 반대편으로 걸어가도 시선이 따라오므로, 대사 없이도 반응의 차이를 시험할 수 있다. 이때 이동 조작은 계속 가능하다.

| 선택 | 위험 또는 비용 | 얻는 정보와 결과 |
|---|---|---|
| 물건을 건드린 뒤 이동해 보기 | 확인하는 데 드는 짧은 탐색 시간 | 컵을 보는 반응과 나를 보는 반응의 차이 |
| 유인에 응할지 가족에게 신호를 보낼지 | 손을 잡으면 실패. 가까이 가거나 관찰하는 것만으로는 실패하지 않음 | 관찰한 증거를 바탕으로 귀환 행동을 선택 |

### 핵심 플레이와 조작

| 입력 | 행동 | 조건 |
|---|---|---|
| A D / ← → | 좌우 이동 | 한 층의 보행선. 점프와 상하 이동 없음 |
| E | 물건 조작 또는 선택창 열기 | 가까운 대상 하나에 안내가 표시될 때 |
| Tab | 귀성 안내서 열기와 닫기 | 플레이 중 확인. 열린 동안 진행 일시정지 |
| Esc | 일시정지 또는 열린 창 닫기 | 위험 선택창에서는 취소로 처리 |
| 마우스 클릭 | 시작과 선택 및 결과 메뉴 | 대화 넘기기는 E도 지원하되 새 입력만 받음 |

주인공은 컵·사진·풍경만 조금 움직일 수 있다. 사람과 직접 대화하거나 불을 스스로 켤 수는 없다. 접근 → E 조작 → 반응 관찰 → 다음 행동의 반복으로 진행하며, 사진을 통한 인사와 가족의 재점화를 거쳐 귀환한다.

### 게임 규칙과 상태

시작 화면, 귀가, 이상 징후, 송별, 성공, 실패의 여섯 상태를 사용한다. 날짜는 조건을 달성한 뒤 전환한다. 안내서와 선택창은 진행을 잠시 멈추는 UI로 처리한다.

| 상태 | 진입 조건 | 허용 행동과 다음 상태 |
|---|---|---|
| 시작 | 실행 또는 처음으로 버튼 | 시작하기 → 첫날 밤 자막 → 귀가 |
| 귀가 | 시작 화면에서 진입 | 컵을 움직인 뒤 실제 가족 오른쪽의 x 7.8 구역에 1초 머물면 확인 완료. 사흘째 저녁으로 전환 |
| 이상 징후 | 날짜 전환 완료 | 컵을 다시 움직이면 가짜의 시선 추적이 시작됨. 가짜의 좌우 관찰 구역을 각각 1초 확인하면 불 끄기 연출 후 송별 |
| 송별 | 가짜가 송별불을 끔 | 사진 세우기 → 풍경 흔들기 → 가족이 현관에 도착해 재점화 → 귀환 구역에서 성공 |
| 성공 | 인사 완료 + 재점화 + 가족 현관 도착 + 귀환 구역에 있음 | 주인공 소멸과 배웅. 결과와 처음으로 및 종료 버튼 표시 |
| 실패 | 송별 상태에서 손잡기 선택을 명시적으로 확정 | 남겨짐 결과. 처음으로 및 종료 버튼 표시 |

#### 실패를 판정하는 순간

눈맞춤과 접근은 안전하다. 가짜가 불을 끈 뒤 "E 손을 내민 사람 살펴보기"를 누르면 "잡지 않는다 / 손을 잡는다"를 보여 준다. 처음에는 거절 쪽을 선택하며 Esc로 취소할 수 있다. 손잡기를 확정했을 때만 "남겨짐"과 실패 원인을 표시한다.

#### 입력과 사건의 우선순위

창을 연 E 입력은 선택 확정에 재사용하지 않으며, 키를 뗀 뒤 새 입력을 받는다. 한 입력은 가장 가까운 활성 대상 하나에만 전달한다. 전환과 결과는 한 번만 처리한다. 선택창이 열려 있으면 귀환 요청을 받지 않으며, 같은 프레임에 유효한 성공·실패 요청이 겹치면 손잡기 확정에 따른 실패를 우선한다. 결과 이후의 요청은 무시한다.

#### 관찰 판정

x 7.8과 x 10.2를 중심으로 폭 0.8 유닛의 구역을 둔다. 첫날에는 x 7.8만 사용한다. 컵 조작 뒤 각 구역에 연속 1초 머물면 완료하며, 완료 전 벗어나면 그 구역의 시간을 다시 센다. 이미 완료한 구역의 기록은 유지한다.

#### 초깃값과 재시작

현관에서 시작하며 컵은 기본 위치, 사진은 기울어짐, 마중불은 켜짐, 가짜는 숨김이다. 관찰·인사·재점화 기록은 거짓이다. "처음으로"는 일시정지를 해제하고 씬을 다시 불러온다[6]. 시작 화면으로 돌아가 위치·방향·물건·불·UI·지연 연출을 초기화한다. 판 사이의 파일 저장은 없다.

### 레벨과 콘텐츠

방과 현관이 한 화면에 들어오는 집 한 채를 사용한다. 컵은 관찰 대상의 왼쪽에 놓고, 그 인물의 오른쪽으로 지나갈 공간을 남긴다. 플레이어가 물건과 다른 쪽으로 이동해야 시선 차이가 드러나므로, 이 거리를 먼저 확보한 뒤 가구를 배치한다.

**그림 2** 전체 맵 설계도. 전체 폭 16 유닛, 한 층의 보행선. 왼쪽은 "불단이 있는 방"(사진·컵·가족의 첫날 자리·왼쪽/오른쪽 관찰 구역·가짜의 자리), 오른쪽은 "현관과 문턱"(풍경·송별불·귀환). 첫날 가족 자리와 사흘째 가짜 자리를 함께 표시했다. 가짜는 첫날 숨겨지고, 실제 가족은 사흘째 불단 쪽에 있다. 화살표와 관찰 구역은 실제 화면에서 숨김.

| 대상 | 수량과 위치 | 용도와 처리 |
|---|---|---|
| 사진 | 1개 / 왼쪽 불단 x 1.5 | 송별 단계에서 세운다. 인사 완료를 기록하며 가족은 사진 쪽을 본다. |
| 컵 | 1개 / 탁자 x 3.5 | 귀가와 이상 징후에서 각각 관찰을 시작한다. 날짜 전환 때 기본 위치로 복원한다. |
| 실제 가족 | 1명 / 첫날 x 5.0, 사흘째 x 2.4 | 물건에 반응한다. 풍경 신호 뒤 x 13.0으로 이동해 재점화하고 불을 지킨다. |
| 가짜 | 1명 / 사흘째 x 9.0 | 컵 조작 이후 플레이어 방향을 따라본다. 손짓으로 불을 끄고 방 안에 남는다. |
| 풍경과 불 | 풍경 x 12.6 / 불 x 14.0 | 풍경은 인사 이후 재점화 요청에 사용한다. 불은 첫날 마중불, 사흘째 송별불로 표현한다. |
| 관찰과 귀환 | 관찰 x 7.8 / 10.2, 귀환 x 14.8 | 관찰 구역은 내부 판정용이다. 귀환 구역 안에 먼저 와 있어도 재점화 후 성공 조건을 다시 확인한다. |

#### 진행을 막지 않는 배치

NPC와 가구는 보행선을 가로막지 않으며, 양 끝 경계만 이동을 제한한다. 컵과 손잡기 대상의 조작 범위는 겹치지 않게 둔다. 사진을 세우기 전에 풍경을 누르면 "떠나기 전에 사진으로 인사를 남기자"라고 안내하고 사용 기회를 소모하지 않는다. 불이 꺼진 문턱에서는 "돌아갈 불이 꺼져 있다"라고 알려 준다.

초회 목표 배분은 도입·학습 40~60초, 반응 비교 60~90초, 인사·귀환 60~90초, 전환·결과 20~30초로 합계 3~4분 30초다. 실측값은 아니며, 예상보다 짧거나 길면 플레이테스트에서 행동을 관찰해 구간별 배분을 조정한다.

### 플레이 화면과 UI

측면 고정 카메라로 방과 현관을 동시에 보여 준다. 기준 화면은 1280×720이며 16×9 유닛을 담는다. NPC의 고개와 몸 방향이 읽히도록 인물 높이는 약 1.6~1.8 유닛으로 잡는다. 배경은 낮은 채도로 두고 얼굴과 손, 상호작용 물건의 윤곽은 구분되게 한다.

**그림 3** 이상 징후 단계의 플레이 화면 설계. 상단에 "사흘째 저녁 / 목표: 컵을 움직인 뒤 저 사람의 반응을 살펴본다", 우상단에 "Tab 안내서 Esc 일시정지", 하단에 "A/D 또는 ←/→ 이동, 상호작용할 수 있는 물건 가까이에서 E". 화면에는 불단과 사진, 실제 가족, 탁자 위 컵, 말줄임표를 띄운 가짜, 플레이어, 현관의 풍경과 송별불이 보인다. 실제 구현 화면은 아니며, 캐릭터의 시선이 읽히는 크기와 배치를 설명한다.

**그림 4** 시작 화면("마중불 / 물건으로 마지막 인사를 남기고, 송별불을 따라 돌아오십시오 / 조작 안내 / 시작하기"), 손잡기 선택창("이번에는 가지 마." / "이 사람의 손을 잡을까요?" / 잡지 않는다 · 손을 잡는다), 성공 결과 화면("귀환 / 가족이 지키는 불을 따라 돌아왔습니다. 사진은 바로 서 있고, 가족은 불 곁에 남아 있습니다." / 처음으로 · 종료). 실패 시 결과는 "남겨짐"으로 바뀐다.

안내서에는 "산 사람은 당신을 볼 수 없습니다", "당신을 바라보는 이가 손을 내밀어도 잡지 마십시오", "인사를 남기고 가족이 지키는 송별불을 따라 돌아오십시오"를 적는다. 이 문구는 작품 안의 규칙이며 진행 중 바뀌지 않는다.

가까운 활성 물건 위에 E와 구체적인 동사를 표시한다. 15초 동안 현재 단계의 조작이나 관찰이 진행되지 않으면 도움말을 한 번 보여 준다. 점화와 인사 완료는 그림 변화와 문구를 함께 사용한다.

일시정지 메뉴는 계속하기·처음으로·종료로 구성한다. 안내서·선택창·일시정지 메뉴를 열면 이동뿐 아니라 관찰 시간, 가족 이동, 사건 대기와 진행 연출도 멈춘다. 닫으면 멈춘 지점에서 이어 간다. 가족 이동 중에도 Esc로 메뉴를 열 수 있다.

### 아트와 사운드 및 에셋

오래된 목조 가옥의 정돈된 생활 공간을 만든다. 배경은 회갈색과 짙은 녹색, 불은 낮은 채도의 주황색을 사용한다. 주인공은 옅은 색으로 구분하되 배경에 묻히지 않게 한다. 공포 장면에서도 얼굴과 손의 방향은 읽혀야 하므로, 화면 전체를 검게 가리는 연출은 사용하지 않는다.

| 에셋 | 수량과 초기 규격 | 제작 방식과 확보 상태 | 대체안 |
|---|---|---|---|
| 배경 | 방과 현관 1장, 1600×900 기준 | 직접 조합할 2D 배경. 제작 전. 구조와 보행선부터 확정 | 단색 벽과 가구 도형 |
| 주인공 | 1종 / 128×192, 대기 1 + 걷기 2장 | 좌우 반전 재사용. 제작 전 | 방향이 보이는 단순 인물 |
| 실제 가족 | 1종 / 128×192, 대기 1 + 걷기 2장 | 반응과 현관 이동에 사용. 제작 전 | 대기 그림과 위치 이동 |
| 가짜 | 1종 / 128×192, 대기와 손 내밀기 2장 | 얼굴 방향과 손동작 우선. 제작 전 | 좌우 반전과 팔 도형 |
| 물건과 불 | 컵·사진·풍경 각 2상태, 불 2프레임 + 꺼짐 | 64~128px 소품. 제작 전. 불단·정령마는 배경 장식 | 상태가 다른 단순 도형 |
| UI와 글꼴 | 패널 1계열 / 버튼 공용, 한글 글꼴 1종 | Unity Canvas로 제작. 글꼴 이용 조건 확인 후 선정 | 기본 패널과 텍스트 |
| 소리 | 필수 효과음 5종, 환경음 최대 1종 | 직접 녹음 또는 이용 조건을 확인한 자료. 미확보 | 동작과 문구로 진행 유지 |

#### 사건별 소리

컵에는 짧은 마찰음, 사진에는 받침이 닿는 소리, 풍경에는 한 번 울리는 종소리를 넣는다. 점화음과 소화음을 더해 필수 효과음은 다섯 종류로 제한한다. 풍경은 실제 가족을 부르는 신호이므로 끝까지 들린 뒤 가족이 반응한다. 가짜가 불을 끌 때는 소화음과 불 그림의 변화가 동시에 나타난다.

환경음은 여름 저녁의 벌레 소리 한 종류를 선택 기능으로 둔다. 음성 녹음과 배경 음악은 필수 범위에서 제외한다. 같은 사건의 반복 입력으로 효과음이 겹치지 않게 하고, 결과 화면에서는 환경음을 낮추어 장면이 끝났음을 알린다.

#### 자료 사용과 일관성

외부 에셋은 아직 선정하지 않았다. 사용할 경우 제작자, 원문 주소, 수정·배포 조건을 기록하고 서로 다른 시점의 팩을 섞지 않는다. 참고 작품의 이미지·음원·코드를 복제하지 않는다. 문서의 화면 그림은 배치를 설명하는 도식이며, 게임용 에셋 확보나 구현 완료를 뜻하지 않는다.

### Unity 구현 계획

Unity 6.6의 Mukaebi 씬 하나에서 시작·플레이·결과를 Canvas 패널로 구분한다. 진행 관리는 GameFlow가 맡고 다른 스크립트는 입력과 사건을 전달한다. 아래 구조는 실제 프로젝트에서 확인할 구현 계획이다.

| 오브젝트와 구성 | 담당할 일 | 연결 대상 |
|---|---|---|
| Player (Rigidbody2D · Collider2D · PlayerController) | 좌우 이동, 최근 대상 하나 선택, E 입력 전달. 중력 0과 회전 고정으로 한 보행선 유지 | 경계 Collider2D, 대상 Trigger |
| Cup · Photo · WindChime (InteractableProp) | 종류와 허용 상태를 확인한 뒤 요청. 승인된 경우 위치나 그림을 바꾸고 소리 재생 | GameFlow, SpriteRenderer, AudioSource |
| Family · Watcher (ActorReaction) | 물건 또는 플레이어의 방향을 바라봄. 가족만 정해진 직선 경로로 현관 이동 | 관찰 대상 Transform, 도착 사건 |
| GameFlow | 현재 단계, 관찰 구역 기록, 인사와 재점화 여부 관리. 전환·방해·결과를 한 번만 실행 | 모든 상호작용 요청과 UI |
| Canvas (UIController) | 목표, E 안내, 안내서, 손잡기 선택, 일시정지, 결과 표시. 다른 조작을 막는 창은 한 번에 하나 | GameFlow, 입력 잠금 |
| Fire · ExitZone | 불 표시와 귀환 구역 체류 여부 관리. 진입·이탈 및 재점화 때 성공 조건을 확인하도록 요청 | GameFlow, Trigger |

#### 핵심 사건의 연결

컵의 E 요청이 승인되면 사용 기록을 먼저 남기고 기본 위치에서 0.18 유닛 옮겨 반응과 소리를 낸다. 같은 단계의 재입력은 위치·소리·관찰 기록을 바꾸지 않는다. 날짜가 바뀔 때 컵 위치와 사용 기록을 초기화한다. 가짜는 사흘째 컵 사용 이후 플레이어의 좌우 위치에 맞춰 방향을 바꾼다.

사진을 세운 뒤 풍경을 울리면 가족이 현관으로 이동한다. 도착 후 재점화하며 인사·점화·도착·귀환 구역 체류가 모두 참이면 성공한다. 먼저 출구에서 기다린 경우도 이때 다시 판정한다. 가족은 불 옆에 남고, 가족이 송별을 지키는 동안 가짜는 불을 다시 끄지 않는다.

#### 조정할 값과 먼저 배울 부분

초기 설정은 이동 속도 2.5 유닛/초, 상호작용 거리 0.8 유닛, 컵 이동 0.18 유닛, 관찰 유지 1초, 도움말 대기 15초다. 모두 Inspector에서 조정한다. 우선 검증할 기능은 양쪽 관찰 구역 판정, 시선 방향 전환, UI 입력 잠금, 가족 이동 완료 사건이다. 기록은 한 판의 메모리에만 두고 재실행 시 복원하지 않는다.

### 개발 범위와 일정

제작 기간은 착수 후 4주로 잡는다. 첫 주에는 분위기 그림보다 반응 차이가 전달되는지 확인하고, 둘째 주까지 시작부터 결과와 재시작을 연결한다. 이후에는 필요한 그림과 소리를 넣고 실제 실행 파일에서 진행이 막히는 문제를 고친다. 날짜별 시간을 채우는 방식보다 주마다 실행 가능한 결과물을 남긴다.

| 주차 | 만들 결과물 | 완료 기준 |
|---|---|---|
| 1주 | 임시 도형으로 이동, 컵, 실제 가족과 가짜의 반응, 관찰 구역 구현 | 설명 없이 플레이어를 옮겨 보며 두 반응의 차이를 확인할 수 있다. 차이가 안 보이면 인물 크기와 배치부터 수정한다. |
| 2주 | 사진, 풍경, 가족 이동, 불, 성공·실패, 시작과 재시작 연결 | 한 번의 실행으로 귀가부터 귀환까지 진행된다. 손잡기 실패와 초기화도 재현된다. 기능 추가를 중단할 기준점이다. |
| 3주 | 배경과 인물, 소품, 필수 효과음, UI 문구 적용. 초회 플레이테스트 | 현재 목표와 위험 선택을 설명 없이 이해하는지 기록한다. 시선 표현과 안내 문구를 우선 수정한다. |
| 4주 | 버그 수정, 해상도 확인, Windows 빌드와 제출 자료 정리 | Editor 밖에서 성공·실패·처음으로를 연속 실행한다. 미완성 선택 기능을 빼고 빌드·영상·문서의 내용이 일치한다. |

#### 필수 기능과 선택 기능

필수 기능은 이동과 E 조작, 물건 3개, 두 NPC의 반응 차이, 세 진행 단계, 사진을 통한 인사, 가족의 재점화, 명시적인 실패 선택, 결과와 재시작이다. 환경음, 불의 추가 프레임, 선택 물건에 대한 짧은 관찰 문장은 필수 기능이 연결된 뒤에만 검토한다.

마을 탐색, 아홉 시간대, 개와 아이의 별도 인식 규칙, 자유 물리 조작, 추격 AI, 인벤토리, 저장 기능, 안내서 위조와 추가 진엔딩은 제작 범위에 포함하지 않는다.

| 문제가 드러나는 시점 | 발생 징후 | 줄이거나 바꿀 부분 |
|---|---|---|
| 1주 종료 | 누가 무엇을 보는지 구분하기 어려움 | 얼굴과 몸 방향을 크게 하고 컵·인물·관찰 지점 간격을 다시 배치 |
| 2주 종료 | 시작부터 결과까지 진행이 끊김 | 부가 대사와 장식 연출 삭제. 상태 연결과 초기화를 먼저 완성 |
| 3주 종료 | 그림 제작이나 NPC 이동이 늦음 | 인물 좌우 반전과 대기 그림을 재사용. 가족 이동은 짧은 화면 전환 뒤 도착 상태로 대체 |
| 4주 | 특정 입력 순서에서 진행 정체 | 새 기능을 넣지 않고 조건·중복 처리 수정. 선택 환경음과 추가 애니메이션 제외 |

목표 제출물은 Windows 실행 빌드, Unity 프로젝트, 한 판 진행 영상, 상세 GDD, 테스트 기록과 에셋 출처 목록이다. 최종 제출 형식과 경로는 수업의 별도 안내에 맞춘다[1].

### 검증 기준과 제작 기록

아래 항목은 구현 뒤 수행할 검증 계획이다. 현재 통과 결과나 플레이 시간 실측값은 없다. 기능별로 조건, 실제 결과, 문제 화면 또는 영상 위치를 기록하고 수정한 항목은 같은 조건으로 다시 확인한다.

| 검증 | 확인할 조건 | 통과 기준 |
|---|---|---|
| 입력과 경계 | 양 끝 이동, 관찰·가족 이동 중 UI 열기 | 맵 밖으로 나가지 않는다. UI 중 이동·조작·관찰 시간·가족 이동·연출이 멈췄다가 이어진다. |
| 정상 반응 | 컵 조작 뒤 가족 반대편으로 이동 | 가족이 컵을 계속 본다. 관찰 구역 1초 뒤 한 번만 날짜가 바뀐다. |
| 이상 반응 | 다시 컵 조작 후 가짜의 좌우로 이동 | 가짜만 플레이어를 따라본다. 이동 조작이 유지되고 조건 충족 전에는 불이 꺼지지 않는다. |
| 선행 조건 | 사진보다 먼저 풍경과 출구 사용 | 이유를 안내하고, 이후 올바른 순서로 다시 진행할 수 있다. |
| 중복 처리 | E 연타, 연출 중 재입력, 동시 결과 요청 | 컵 위치와 기록이 누적되지 않는다. 사건은 한 번만 실행되며 동시 결과는 실패가 우선한다. |
| 공정한 실패 | 시선 확인, 가짜 접근, 선택 취소·확정 | 관찰과 접근은 안전하다. 새 입력으로 손잡기를 확정했을 때만 실패한다. |
| 성공 조건 | 필수 조건 누락, 재점화 전에 출구에서 대기 | 조건이 빠지면 성공하지 않는다. 구역 체류 중 나머지 조건이 충족돼도 한 번만 성공한다. |
| 재시작 | 성공·실패·가족 이동 중 처음으로 선택 | 시작 화면으로 복귀하고 이전 판의 물건·불·방향·기록·지연 연출이 남지 않는다. |
| 빌드와 화면 | Windows 빌드에서 1280×720·1920×1080 실행 | 글자와 버튼이 잘리지 않고 성공·실패·재시작을 모두 재현한다. |

#### 플레이테스트

처음 보는 사람 3명을 목표로 설명 없이 한 판을 진행하게 한다. 컵 뒤에 스스로 이동했는지, 무엇을 근거로 가짜를 의심했는지, 풍경의 용도를 이해했는지와 걸린 시간을 기록한다. 종료 후 "이상함을 처음 느낀 순간"과 "다음 행동을 몰랐던 위치"를 묻는다. 인원은 검증 계획이며 테스트 완료 인원이 아니다.

#### 기획 과정과 AI 활용

ChatGPT를 기획 범위 검토, 규칙과 상태 조건 정리, 문서 초안과 화면 도식 구성에 활용했다. 요청의 요지는 1인 4주 제작에 맞게 마중불을 구체화하는 것이었다. 시선 관찰을 핵심으로 남기고 아홉 시간대와 추가 엔딩을 줄였으며, 눈맞춤 즉사와 실제 타이머 없는 시간 초과 실패는 규칙에서 뺐다. 검토 결과는 이 문서에 반영했으며, Unity 동작과 재미의 검증은 위 테스트로 진행한다.

## 3 결론

완성할 게임은 가족에게 흔적을 남기는 행동이 낯익은 존재의 정체를 드러내는 짧은 공포 게임이다. 물건 하나를 움직인 뒤 반응을 직접 확인하는 장면과, 가족이 지키는 불을 통해 떠나는 결말을 먼저 완성한다. 기능의 수보다 이 두 장면이 플레이어의 조작으로 자연스럽게 이어지는지를 제작의 기준으로 삼는다.

## 4 참고문헌

과제의 구성과 범위, 배경 풍습, 구현 시 사용할 기능을 확인한 자료다. 문화 자료의 사진과 참고 게임의 이미지·음원·코드는 게임 에셋으로 사용하지 않는다. 아래의 민속 설명과 작품 안에서 새로 정한 규칙은 구분한다.

1. 닛코산 린노지, 「夏の思い出」, 2023년 8월 1일. https://www.rinnoji.or.jp/news/20230801.html — 마중불과 송별불, 오이 말과 가지 소에 관한 풍습 설명을 참고했다.
2. 교토관광 공식 사이트, 「京都五山送り火の成り立ちと左大文字保存会の活動」. https://plus.kyoto.travel/entry/okuribi — 조상을 맞이하고 보내는 의미, 정령마에 담긴 귀환과 이별의 마음을 참고했다. 특정 지역의 관행을 모든 지역의 고정 규칙으로 쓰지 않았다.
3. Nintendo, 「Ghost Trick Phantom Detective」 공식 소개. https://www.nintendo.com/en-gb/Games/Nintendo-DS/Ghost-Trick-Phantom-Detective-270880.html — CAPCOM이 제공한 작품 소개다. 사물 조작으로 산 사람의 반응을 유도하는 선행 사례로 비교했다. 본 기획은 반응 차이로 유인자를 판단하는 데 초점을 두고 복잡한 사물 연쇄 퍼즐은 채택하지 않았다.
4. Unity Technologies, 「SceneManager.LoadScene」 문서. https://docs.unity3d.com/6000.0/Documentation/ScriptReference/SceneManagement.SceneManager.LoadScene.html — 현재 씬을 다시 불러오는 재시작 방식의 참고 자료다. 프로젝트 설정과 초기화 결과는 실제 빌드에서 검증한다.

참고 작품에서 가져올 점은 말로 직접 설명하기 어려운 상황을 물건 조작으로 드러내는 방식이다. 마중불에서는 한정된 공간의 두 반응을 비교하고 마지막 신호를 보내는 흐름으로 좁힌다. 실제 배경·인물·음원은 제작 단계에서 별도로 확보하고 사용 조건을 기록한다.
