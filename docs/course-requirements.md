# 수업 요구 사항 대조표

출처: 게임엔진1 8주차 중간고사 GDD 가이드 (https://creativeengineer-kimjungho.com/teaching/game-engine-1/week-08-midterm.html), 2026-11-09 확인.
상태 표기: 충족 / 보완 필요 / 미작성.

## 평가 기준 (중간고사 = 전체 성적 20%)
| 기준 | 질문 | v3에서 지킬 것 |
|---|---|---|
| 게임의 명확성 | 목표와 핵심 플레이가 분명한가 | 핵심 플레이는 "소리를 내 아이를 움직인다" 하나. 목표는 날마다 목표 줄 한 줄(알리기 → 지키기 → 불단에 인사 → 반전 후 상자·등롱). 반전 후 목표가 바뀌는 것이 의도된 구조임을 GDD에 명시한다 |
| 재미의 설득력 | 재미를 만드는 행동과 선택을 설명했는가 | 같은 조작의 쓰임이 날마다 바뀜(알리기 → 주의 돌리기 → 상자 부르기). 선택·위험·보상 표: 노크를 막을지(연 횟수만큼 사흘째 추적이 빨라짐), 쫓기며 불단까지 가는 길, 반전 후 상자를 열지·바로 대문으로 갈지·비켜설지 |
| 설계의 구체성 | 규칙과 화면 스케치가 구체적이며 서로 일치하는가 | 48×32 지도 그림과 단계별 화면을 `HouseSceneBuilder.cs` 문자 지도와 일치시키고, 규칙표 수치(듣는 거리 14걸음, 첫날 3개, 노크 3번·간격 5초, 추적 2.4+0.25×연 횟수 걸음/초, 송별불 180초)를 코드 값과 맞춘다 |
| 계획의 현실성 | 학기 안에 완성 가능한가 | 수업 권장 일정(11~16주)에 맞춘 roadmap, 필수/선택/제외 구분. 줄일 곳(문밖 구간 → 현관에서 다시 시작)을 미리 적는다(ADR 0006) |

## 필수 10항목
| # | 항목 | v1 상태 | 최종 GDD(gdd-v2.md, v3 설계)에서 보완 |
|---|---|---|---|
| 1 | 게임 개요 (한 문장 소개 포함) | 보완 필요 | 한 문장 소개(story.md 1절). 시점을 "탑다운 4방향 격자"로, 플레이 시간을 "목표 약 20분(측정 전)"으로 바꾼다. 문서 앞에 **문서 버전·수정일** 추가 (v1 표지에 없음) |
| 2 | 기획 의도와 핵심 재미 | 보완 필요 | 반전("내 불단이 아니었다")과 날마다 바뀌는 소리 조작을 중심으로. 선택·위험·보상 표. 서사는 배경 3문장 + 서사-규칙 대응표(story.md 2절)로만 |
| 3 | 핵심 플레이와 조작 | 충족 | 조작표를 현재 입력으로 교체: 방향키/WASD 한 칸 이동, Shift 달리기, E·Space·Enter 조사(앞 칸 안내), M 미니맵, R 처음부터. v1의 Tab 안내서·Esc 일시정지·마우스 메뉴는 현재 코드에 없으므로 유지 여부를 정해 표기 |
| 4 | 게임 규칙과 상태 | 보완 필요 | 상태(`HousePhase`: 오프닝·첫날·둘째 날·사흘째·문밖·반전 후·연출·결말)와 전환 조건 표. 결말 4종 판정과 우선순위(비켜섬 > 등롱+대문 > 송별불+대문 > 시간 초과, `EndingRule`). 수업이 요구하는 성공·실패 조건을 4종에 어떻게 대응시킬지 명시 |
| 5 | 레벨과 콘텐츠 | 보완 필요 | 집 지도(방 9개 + 마당·창고), 방별 소품·조사 문장 표. **난이도 변화** 절: 첫날 소리 학습(시간 압박 없음) → 둘째 날 노크 시간 압박 → 사흘째 추적(둘째 날 결과로 속도 변화) → 반전 후 180초 |
| 6 | 플레이 화면과 UI | 보완 필요 | 목표 줄, 앞 칸 E 안내, 미니맵, 사진 클로즈업(반전), 선택창, 결말 화면 4종 스케치 |
| 7 | 아트·사운드와 에셋 | 보완 필요 | 현재 도형·코드 생성 소리임을 밝히고, 교체 계획(규격, 에셋별 출처·이용 조건·대체안)을 적는다. "직접 제작 128×192"는 폐기 |
| 8 | Unity 구현 계획 | 보완 필요 | 현재 프로토타입에서 **확인한 기능(근거)**과 **구현 계획**을 구분해 표기 (가이드 요구). 근거는 production-log.md의 검증 상태를 따른다 |
| 9 | 개발 범위와 일정 | 보완 필요 | "착수 후 4주"를 수업 주차(11~16주) 기준으로 재작성. 범위 변경(여러 방·격자 추적 허용, 결말 4종)을 v1 범위와 비교해 설명 |
| 10 | 검증 기준과 제작 기록 | 보완 필요 | 검증 표에 상태 열(예정/확인 완료/수정 필요). 행 예: 결말 4종 각각 재현, 노크 막음/열림 모두 다음으로 진행, 문밖에서 다시 들어오기, 상자 연 뒤 불 타이머 정지, 반전 전 출구 막힘. 플레이테스트 기록, 출처, AI 활용, **변경 이력**은 production-log.md |

## 최종(16주) 제출물
실행 파일, Unity 프로젝트, 한 판 진행 영상, 제작 기록. 상세 GDD의 재제출 여부와 세부 배점·제출 경로는 별도 공지 확인 필요.

## 수업 권장 일정
| 주차 | 권장 결과물 |
|---|---|
| 9~10 | 블록아웃 보완, 아트 기준과 에셋 키트 준비 |
| 11~12 | 필수 규칙을 통합한 플레이 빌드 |
| 13 | 알파 빌드와 3인 플레이테스트 기록 |
| 14~15 | 면담 반영, 제출 후보 빌드, 기능 추가 종료 |
| 16 | 최종 실행 파일, 프로젝트, 영상, 제작 기록 제출 |

## 교수님·조교 확인 질문 (/to-questionnaire 입력)
1. 최종 제출 시 상세 GDD 개정본도 제출하는가, 제작 기록에 변경 이력만 포함하면 되는가?
2. 16주차 제출 일시와 경로, 영상 길이 기준
3. 외부 무료 에셋 사용 시 출처 표기 형식
4. 면담(14~15주) 일정과 준비물
5. 결말이 4종(배웅·빼앗은 불·남은 자리·꺼진 불)이고 "게임 오버"가 없는 구조에서 성공·실패 조건을 어떻게 적으면 되는가?
6. 중간 GDD와 시점·서사가 크게 바뀐 경우(측면 → 탑다운, 반전 서사) 평가에서 따로 요구하는 설명이 있는가?
